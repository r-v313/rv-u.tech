# قائمة فهم الـTarget — RVU Camp
By Ramez Medhat · rv-u.tech

استخدم القائمة لبناء صورة واضحة عن التطبيق قبل زيادة الأدوات الناتج المطلوب خريطة صغيرة + أسئلة مرتبة + دليل لكل اختبار

## ١ حدود الشغل
- [ ] دون الأصول المسموحة والاستثناءات وقواعد الحسابات والطلبات
- [ ] تأكد أن أي نطاق أو رابط جديد داخل النطاق قبل التفاعل معه
- [ ] حدد حسابات الاختبار التي تملكها والأدوار المتاحة

## ٢ الاستخدام الطبيعي
- [ ] جرب الوظائف الأساسية كما يفعل المستخدم إنشاء عرض تعديل إلغاء
- [ ] تابع الطلبات والاستجابات في Burp Suite
- [ ] حدد أين تخزن الجلسة وكيف تتغير أثناء الدخول والخروج
- [ ] ارسم خطوات الـWorkflow والحالات المسموحة للانتقال بينها

## ٣ خريطة التطبيق
أنشئ جدولا بالأعمدة الوظيفة | المسار | طريقة الطلب | الدور | المورد | الأثر المحتمل | ملاحظات
- [ ] اجمع المسارات المرتبطة بالوظائف المهمة من حركة التطبيق والـJavaScript والتوثيق المتاح
- [ ] اربط كل معرف بالمورد وصاحبه
- [ ] دون الوظائف الحساسة مثل استرجاع الحساب وتغيير البريد وإدارة الأدوار والدفع
- [ ] اكتب ما لا تفهمه بدل افتراضه

## ٤ فرضيات قابلة للاختبار
- [ ] هل يفحص الدور وملكية المورد في كل خطوة؟
- [ ] هل يؤكد السيرفر السعر والكمية والحالة بنفسه؟
- [ ] هل يتغير السلوك بين الواجهة ومسار API المقابل؟
- [ ] هل يمكن الانتقال لحالة قبل استكمال شروطها؟
- [ ] لكل فرضية Baseline تغيير واحد نتيجة متوقعة ودليل مطلوب

## ٥ الأولوية والمراجعة
- [ ] ابدأ بالوظائف الحساسة والأسئلة التي تملك حسابات وموارد مناسبة للتحقق منها
- [ ] سجل نتائج الاختبارات السلبية أيضا
- [ ] ميز بين أثر حقيقي على السيرفر وتغيير محلي في الواجهة
- [ ] احتفظ بخطوة تالية واضحة قبل التوقف

وجود أدوات أكثر لا يعني خريطة أوضح قياس التقدم هل تعرف ماذا تختبر ولماذا وما الدليل الذي سيؤكد النتيجة؟
